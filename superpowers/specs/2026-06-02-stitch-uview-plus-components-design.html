# Stitch uview-plus Components Design

  • Date: 2026-06-02
  • Topic: Add a new stitch-uview-plus-components skill to partme-ai/full-stack-skills
  • Goal: Contribute an independent Stitch conversion skill for uview-plus that is stronger than the existing stitch-uviewpro-components, and update repository discovery surfaces so the new skill is installable and documented.

# Scope

# In Scope

  • Add a new skill directory at skills/stitch-skills/stitch-uview-plus-components/
  • Default generated output to uview-plus up-* components
  • Make the skill explicitly target uni-app + Vue 3 + uview-plus
  • Include richer framework guidance than stitch-uviewpro-components
  • Update skills/stitch-skills/README.md
  • Update skills/stitch-skills/README_CN.md
  • Update .claude-plugin/marketplace.json

# Out of Scope

  • Refactoring stitch-uviewpro-components
  • Changing existing non-related Stitch skills
  • Creating a new plugin group
  • Fixing unrelated repo inconsistencies

# Positioning

This new skill is not a copy or rename of stitch-uviewpro-components. It is a dedicated uview-plus skill with a stronger engineering and framework contract:

  • uses up-* by default
  • aligns to uview-plus current documentation and project setup
  • covers theme variables, dark mode, safe area, and status bar concerns
  • covers more component mappings and stronger anti-pattern guidance
  • requires more structured output than a single converted page

# Functional Design

# Trigger and Intent

The skill activates only when the user explicitly mentions Stitch and asks for conversion to uview-plus, up-*, or uni-app + Vue 3 + uview-plus.

# Retrieval Flow

  1. Resolve Stitch project/screen via URL parsing or stitch-mcp-list-projects + stitch-mcp-list-screens
  2. Fetch screen metadata via stitch-mcp-get-screen
  3. Download htmlCode via scripts/fetch-stitch.sh
  4. Use screenshot as visual reference
  5. Convert structure into modular uview-plus page/component output

# Output Rules

  • Default to up-* components
  • Prefer page + shared components + data modules over one large page file
  • Prefer framework-native patterns over raw HTML reproduction
  • Preserve Stitch layout intent while rewriting into uni-app structure

# Differentiators vs stitch-uviewpro-components

# Stronger Framework Alignment

  • Explicit uview-plus setup guidance: uni_modules/uview-plus, main.js, App.vue, uni.scss, easycom, setConfig
  • Explicit current uview-plus theme system guidance
  • Explicit --up-* variable and styling guidance where relevant

# Stronger Runtime/Page Rules

  • up-status-bar
  • up-safe-bottom
  • bottom CTA handling
  • safe area adaptation
  • dark mode / theme adaptation expectations

# Broader Component Mapping

The skill should cover at least these common mappings beyond form basics:

  • up-popup
  • up-upload
  • up-subsection
  • up-tabbar
  • up-empty
  • up-gap
  • up-line
  • plus standard navigation, form, picker, tabs, card-like structures

# Stronger Anti-Patterns

The contract should explicitly forbid generating raw interactive HTML when an appropriate up-* component exists. Examples include raw button/input/modal/tabs/card structures.

# Stronger Engineering Output

The skill should encourage generation of:

  • page files
  • shared components
  • mock/static data extraction
  • theme notes
  • structured checklists

# File Responsibilities

# SKILL.md

Defines trigger conditions, retrieval workflow, generation constraints, and engineering expectations.

# examples/usage.md

Contains multiple realistic trigger examples including:

  • direct Stitch URL conversion
  • project/screen browsing flow
  • login/register form page
  • tabbar home page
  • popup/upload interactions

# references/official.md

Links to official uview-plus docs for setup, components, guides, theme, dark mode, and related areas.

# references/contract.md

Core conversion contract. Must define:

  • component mapping rules
  • slots / events / v-model expectations
  • forbidden raw HTML fallbacks
  • page structure rules
  • safe area and status bar patterns

# references/component-index.md

A practical generation-time component selection guide, grouped by category.

# references/stitch-html-patterns.md

Rules for turning Stitch HTML into uni-app page regions and reusable structures.

# references/tailwind-to-uview-plus.md

Maps Tailwind spacing, colors, radii, shadows, and typography into rpx, theme tokens, and uview-plus style conventions.

# resources/architecture-checklist.md

Post-generation QA checklist.

# resources/page-template.vue

An enhanced page scaffold for uview-plus page generation.

# scripts/fetch-stitch.sh

Reliable Stitch HTML downloader.

# api/component-api.md

Quick contract reference for easy-to-misuse components such as tabs, form, picker, popup, upload, and tabbar.

# Risks and Controls

# Risk: Too similar to stitch-uviewpro-components

Control: write new contract, broader component coverage, stronger setup/theme/runtime guidance, and distinct wording.

# Risk: Drift from actual uview-plus docs

Control: source mappings from current local uview-plus docs and align official/reference links accordingly.

# Risk: PR gets rejected as redundant

Control: make README wording and skill scope clearly distinguish uview-plus from uView Pro and emphasize additional capabilities.
