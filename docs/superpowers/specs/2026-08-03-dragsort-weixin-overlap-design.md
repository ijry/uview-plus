# Dragsort 微信小程序重排覆盖修复设计

## 背景

`u-dragsort` 在 H5 拖动排序正常，但在微信小程序中拖动并松手后，部分列表项会停留在相同位置并发生覆盖。问题出现在排序阶段，不是首次挂载的尺寸测量阶段。

当前组件在 `reorderItems` 中直接对 `list` 执行 `splice`。虽然 Vue 列表 key 使用 `item.id`，但原生 `movable-view` 的 `id` 和事件回调参数仍使用数组索引。重排后，同一个数据项继续复用原生节点，但节点 id 和事件闭包中的 index 都可能滞后于当前列表；微信小程序在触摸结束与视图更新交错时会保留旧节点坐标或用旧 index 继续重排，导致项目覆盖。H5 的 DOM 更新和事件刷新更及时，因此表现存在平台差异。

## 目标

- 修复微信小程序拖动松手后的列表项覆盖。
- 同时覆盖 `vertical`、`horizontal` 和 `all` 三种方向模式。
- 保持现有 props、插槽、拖动过程和 `drag-end` 返回结果不变。
- 增加可重复执行的静态回归校验，避免原生节点标识再次退化为索引。

## 非目标

- 不重写现有排序算法和 `movable-view` 方案。
- 不调整拖动阈值、震动、阴影或动画时长。
- 不改变调用方传入列表和接收 `drag-end` 的方式。
- 不处理图片异步加载造成的首次尺寸测量偏差；该问题与本次松手后覆盖无关。

## 方案比较

### 方案一：让原生节点标识跟随组件实例和数据项

保留 `:key="item.id"`，并将 `movable-view` 的 `id` 改为“组件实例前缀 + `item.id`”的稳定值。数组重排只改变位置数据，不再改变原生节点身份；同一页面存在多个拖动排序实例时也不会产生重复 id。

该方案可以消除 Vue key 与原生 id 的身份冲突，但微信真机验证表明，单独稳定 id 仍不足以避免 `movable-view` 重排覆盖。

### 方案二：拖动结束后销毁并重建节点

通过额外版本号修改 key，强制微信小程序重新创建全部 `movable-view`。可以清除旧坐标，但会引入闪烁、额外渲染和拖动状态切换复杂度。

### 方案三：拖动期间不重排原生节点数组（最终采用）

维护独立的视觉顺序 `orderIds`，渲染 `list` 始终保持原生节点顺序稳定。拖动时只更新 `orderIds` 和每项坐标，插槽 index 与 `drag-end` 按视觉顺序计算。稳定 id 的最小方案经微信真机验证仍会覆盖，因此最终采用该方案。

## 实现设计

1. 在 `u-dragsort.vue` 中为每个组件实例生成一次稳定前缀。
2. 将每个 `movable-view` 的原生 `id` 从数组索引改为“组件实例前缀 + 数据项 `id`”。
3. 将 `change`、`touchstart` 事件参数从数组 index 改为稳定的 `item.id`。
4. 新增 `orderIds` 维护视觉顺序，拖动重排只修改 `orderIds`，不再对渲染 `list` 执行 `splice`。
5. `updatePositions` 通过 `orderIds` 计算每个稳定节点的目标坐标；插槽 index 也从 `orderIds` 获取。
6. `drag-end` 根据 `orderIds` 组装排序结果，保持原有事件返回语义。
7. 外部 `initialList` 回写时保留已有节点的渲染顺序，只同步数据、增删节点和视觉顺序。
8. 新增 `scripts/verify-dragsort-stable-identity.mjs`，断言原生 id、事件回调与重排逻辑都不依赖数组 index。
9. 在 `package.json` 注册 `verify:dragsort-stable-identity`。

## 兼容性

- `initialList` 已要求每项具备稳定 `id`，示例和现有模板 key 都依赖该字段，本次不新增公开约束。
- `id` 会拼接组件实例前缀，避免直接输出业务值，并保证同页多个组件实例之间不冲突。
- 三种方向模式共用同一节点身份策略，排序计算和事件结构不变。

## 验证

- 先运行新增校验，确认当前索引 id 实现失败。
- 修改组件后运行 `npm run verify:dragsort-stable-identity`。
- 执行 `npm run build:mp-weixin`，确认模板能正常编译为微信小程序产物。
- 检查编译后的 WXML，确认 `movable-view` 的 `id` 来自数据项稳定字段而非循环索引。
- 使用微信开发者工具手工拖动纵向、横向和多行多列示例，确认松手后无覆盖且 `drag-end` 顺序正确。
