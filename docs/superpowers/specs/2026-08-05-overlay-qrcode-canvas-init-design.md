# Overlay 内二维码画布初始化修复设计

## 背景

H5 中将 `up-qrcode` 放入初始隐藏的 `up-overlay` 插槽后，首次打开遮罩时可能出现二维码绘制不完整或画布为空；同一二维码直接放在页面中时显示正常。

问题由 `up-canvas` 统一承载改造后的初始化时序引入。`up-canvas` 在自身 `mounted` 阶段自动调用 `initCanvas()`，`up-qrcode` 的 `mounted` 阶段也会调用子画布的 `initCanvas()`。Overlay 通过 `u-transition` 动态挂载插槽内容，两次异步节点查询更容易并发执行。

实测中，同一画布会同时进入两次非强制初始化。若较晚返回的初始化在二维码绘制后继续设置 canvas 宽高并清屏，已绘制内容会被重置。人为延迟首次初始化即可稳定得到全透明画布，证明故障来自初始化竞争，而不是二维码矩阵算法或 Overlay 样式裁剪。

## 目标

- 同一 `up-canvas` 实例的并发初始化只执行一次实际节点初始化。
- `up-qrcode` 在 Overlay 动态挂载场景中首次显示即可完整绘制。
- 保持 `initCanvas(force)`、`refresh()`、`ready` 事件和现有业务组件调用方式不变。
- 在 Overlay 示例中加入二维码组合场景，便于 H5 人工回归。
- 增加可重复执行的验证脚本，覆盖初始化竞争与示例接入。

## 非目标

- 不修改二维码编码、矩阵计算或绘制算法。
- 不改变 Overlay 或 Transition 的动画生命周期。
- 不调整 `up-canvas` 的公开属性和绘图 API。
- 不进行版本发布、版本号变更或提交推送。

## 方案

在 `up-canvas` 实例上保存当前初始化 Promise。`initCanvas()` 开始时先检查是否已有初始化正在执行；存在时直接返回同一个 Promise，不再重复查询节点、设置 canvas 尺寸或清屏。

首次调用负责完成现有初始化流程：按需测量根节点、查询 canvas 节点、设置 DPR backing store、获取上下文、应用字体、清理画布并发出 `ready`。无论成功、失败或异常，完成后都释放初始化 Promise，使后续显式重试或 `refresh()` 可以再次执行。

`force=true` 在没有进行中初始化时仍会重新初始化；若调用时已有初始化进行中，则等待该初始化结果。正在创建的画布不需要再并发执行一次强制重置，合并调用可以避免同一节点被重复清空。

## 示例

在 `src/pages/componentsA/overlay/overlay.nvue` 增加“嵌入二维码”入口和独立的显示状态。对应 Overlay 插槽中放置居中的白色内容区域与固定尺寸 `up-qrcode`，二维码仅在 Overlay 首次打开时随插槽动态挂载，从而覆盖本次回归条件。

示例使用独立且固定的 `cid`，避免与页面其他画布冲突。点击遮罩仍沿用现有示例交互关闭，不增加额外说明性界面。

## 验证

- 新增 Node 验证脚本，模拟同一 `up-canvas` 的两个并发初始化调用，断言底层节点初始化只执行一次且两个调用得到相同结果。
- 验证脚本检查 Overlay 示例包含独立二维码状态、入口和 `up-qrcode` 插槽内容。
- 运行现有 `verify:up-canvas-unification`，确保统一画布约束仍成立。
- 运行 H5 构建，检查 Vue 模板与条件编译。
- 启动 H5 示例并打开“嵌入二维码”，确认二维码四个定位角及完整矩阵均显示，重复关闭和打开后仍正常。

## 风险与兼容性

初始化 Promise 属于组件实例私有状态，不改变公开接口。合并并发强制初始化意味着进行中的初始化会优先完成，而不是被第二次强制初始化打断；对于尚未 ready 的同一 canvas，这是预期行为，并能消除尺寸重置竞争。

改动位于共享 `up-canvas`，因此需要运行现有统一画布验证和 H5 构建，确认条码、裁剪、海报等调用方的静态契约未受影响。
