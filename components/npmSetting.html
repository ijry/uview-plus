# NPM安装方式配置

# 关于SCSS

uview-plus依赖SCSS，您必须要安装此插件，否则无法正常运行。

  • 如果您的项目是由HBuilder X创建的，相信已经安装scss插件，如果没有，请在HX菜单的 工具->插件安装中找到"scss/sass编译"插件进行安装， 如不生效，重启HX即可
  • 如果您的项目是由vue-cli创建的，请通过以下命令安装对sass(scss)的支持，如果已安装，请略过。
// 安装sass
npm i sass@1.63.2 -D

// 安装sass-loader，注意需要版本10，否则可能会导致vue与sass的兼容问题而报错
npm i sass-loader@10.4.1 -D

# 准备工作

在进行配置之前，请确保您已经根据安装中的步骤对uview-plus进行了npm安装，如果没有，请先执行安装：

// 如果您的项目是HX创建的，根目录又没有package.json文件的话，请先执行如下命令：
// npm init -y

// 安装
npm install uview-plus
npm install dayjs
npm install clipboard

# 配置步骤

# 引入uview-plus主JS库

在项目src目录中的main.js中，引入并使用uview-plus的JS库，注意这两行要放在const app = createSSRApp(App)之后。

// main.js
import uviewPlus from 'uview-plus'

// #ifdef VUE3
import { createSSRApp } from 'vue'
export function createApp() {
  const app = createSSRApp(App)
  app.use(uviewPlus)
  return {
    app
  }
}
// #endif

# 在引入uview-plus的全局SCSS主题文件

在项目根目录的/src/uni.scss中引入此文件, 如果不存在/src/uni.scss自己创建一个空白文件。

注意！

请注意uni-app官方规范中uni.scss是一个特殊文件，万万不可将其它样式比如uview-plus/index.scss引入至uni.scss中，否则会造成打包后包超大。

/* uni.scss */
@import 'uview-plus/theme.scss';

3.8+ 主题说明

theme.scss 仍需保留，它负责兼容旧 uni.scss 里的 $u-* 覆盖；但从 3.8+ 开始，主题体系已经逐步迁移到 --up-* CSS变量 + 运行时主题方案。旧 $u-* 只桥接 light，不会自动生成 dark。

theme.json 只负责声明式默认值，导航栏和页面最终效果会受到运行时主题接管。旧项目升级时，请优先阅读：

  • 自定义主题 / CSS变量迁移说明
  • 暗黑模式与运行时主题说明

nvue 项目必须启用 Root 组件

如果项目中存在 .nvue 页面，必须继续按 Root 根组件 文档启用 UniUpRoot，同时保留 App.up.vue 中的 <UpRootView />。

当前 nvue 页面的主题能力依赖 Root 注入。未启用时，页面中的 upThemeVar、upThemePageStyle、upThemeIsDark 等能力不会挂到实例上，运行时可能直接报错或白屏，典型报错如下：

  • TypeError: this.upThemeVar is not a function
  • Property "upThemePageStyle" was accessed during render but is not defined on instance

# 配置取消Saas报警

取消“The legacy JS API is deprecated and will be removed in Dart Sass 2.0.0.”类似的报警。 在根目录vite.config.js（没有则新建）中增加如下代码中的silenceDeprecations字段:

import { defineConfig } from "vite";
import uni from "@dcloudio/vite-plugin-uni";
import { visualizer } from "rollup-plugin-visualizer";

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [
    uni(),
	visualizer()
  ],
  css: {  
	preprocessorOptions: {  
	  scss: {  
		// 取消sass废弃API的报警
		silenceDeprecations: ['legacy-js-api', 'color-functions', 'import'],  
	  },  
	},  
  },
  server: {
    port: 5100,
    fs: {
        // Allow serving files from one level up to the project root
        allow: ['..']
    }
},
});

# 配置easycom组件模式

此配置需要在项目src目录的pages.json中进行。

温馨提示

  1. uni-app为了调试性能的原因，修改easycom规则不会实时生效，配置完后，您需要重启HX或者重新编译项目才能正常使用uview-plus的功能。
  2. 请确保您的pages.json中只有一个easycom字段，否则请自行合并多个引入规则。

uview-plus3.x配置

// pages.json
{
	"easycom": {
		"autoscan": true,
		// 注意一定要放在custom里，否则无效，https://ask.dcloud.net.cn/question/131175
		"custom": {
			"^u--(.*)": "uview-plus/components/u-$1/u-$1.vue",
			"^up-(.*)": "uview-plus/components/u-$1/u-$1.vue",
	        "^u-([^-].*)": "uview-plus/components/u-$1/u-$1.vue"
		}
	},
	
	// 此为本身已有的内容
	"pages": [
		// ......
	]
}

uview-plus4.x配置（尚未发布）

// pages.json
{
	"easycom": {
		"autoscan": true,
		// 注意一定要放在custom里，否则无效，https://ask.dcloud.net.cn/question/131175
		"custom": {
			"^up-(.*)": "uview-plus/components/up-$1/up-$1.vue",
		}
	},
	
	// 此为本身已有的内容
	"pages": [
		// ......
	]
}

# APP本地字体图标配置 3.8.82

默认情况下，H5 和小程序端的 uview-plus 图标字体通过网络 CDN 加载。Android App 在弱网环境下如果依赖远程字体，可能导致图标无法显示。

从 3.8.82 起，APP / APP-NVUE 内置图标字体已随 uview-plus 包分发。组件内部通过 components/u-icon/upicon.ttf?url 让构建产物自动发射字体资源，并在运行时通过 uni.loadFontFace / nvue dom.addRule 加载本地字体。

APP 端无需额外配置，不需要添加 Vite 插件或复制字体文件。按前面的安装步骤正常引入 uview-plus 即可。

实际加载规则：

  1. APP / APP-NVUE：使用包内 components/u-icon/upicon.ttf 生成的本地字体资源
  2. H5、微信小程序、支付宝小程序等非 App 平台：继续使用 config.iconUrl 远程字体

TIP

这项能力只改变 APP / APP-NVUE 的内置图标字体来源。自托管图标字体或扩展自定义图标仍按图标组件文档中的 iconUrl / customIcon 配置处理。
